# 棋見：本機西洋棋棋局檢討工具

> 文件狀態：需求訪談後初版  
> 目標使用者：專案擁有者（個人使用）  
> 平台：macOS（32 GB RAM）

## 1. 產品目標

做一個**本機優先（local-first）**的西洋棋賽後檢討工具。使用者在 Chess.com 下完一局後，複製 PGN、貼進工具，即可得到深入但白話的逐步復盤：勝率曲線、每步最佳著、失誤判定，以及像教練旁白般的策略解釋。

工具的體驗要接近 Chess.com 的棋局分析：左／中間是可操作的棋盤，右側是逐步分析與講評；但棋譜和運算不需要傳到雲端。

## 2. 本機與隱私決策

第一版採用「本機網頁 App」：在 Mac 的瀏覽器開啟，但所有程式與 Stockfish 引擎皆從本機載入，PGN、棋局狀態與分析結果不會上傳。

這**不等於雲端運算**。網頁只是介面；Stockfish WebAssembly 在本機 CPU 上工作。它可被做成 PWA，從 macOS Dock／應用程式資料夾啟動，外觀與日常使用上接近 App。首次安裝依賴套件時需要網路；完成建置後，日常分析不需要網路。

第二階段再視需要用 Tauri 將同一個前端包成原生 macOS `.app`。這不是 MVP 的前置條件，避免過早增加打包、簽名與發佈複雜度。

## 3. 已確認需求

| 面向 | 決定 |
| --- | --- |
| 輸入 | 僅支援手動貼上標準 PGN；不做帳號登入、連結匯入、檔案上傳 |
| 棋局來源 | Chess.com 對局為主要來源，但任何合法標準 PGN 都可分析 |
| 分析方式 | 可容許較長等待時間，以深入分析優先 |
| 運算位置 | 優先完全在 Mac 本機 CPU 運算 |
| 主要輸出優先序 | 1. 勝率曲線 2. 失誤分類 3. 深入白話解釋 4. 每步最佳著 |
| 解釋風格 | 白話、但有策略與局面評估；不是只報引擎數字 |
| 回放 | 分析完成後可互動棋盤逐步播放、跳轉任一步 |
| 介面 | 視覺與操作邏輯接近 Chess.com 分析頁：棋盤 + 評估條 + 側欄旁白 |
| 使用者與發佈 | 個人使用；日後可能放 GitHub |

## 4. MVP 功能範圍

### 4.1 PGN 輸入與驗證

- 大型貼上區，接受含標頭、註解與結果的標準 PGN。
- 顯示可理解的錯誤，例如「第 12 手記譜不合法」，而非技術例外。
- 讀取 `White`、`Black`、`Date`、`Result` 等可用標頭。
- 不儲存或上傳原始棋譜；重新整理後預設清除（除非後續另行要求本機儲存）。

### 4.2 本機引擎分析

- 使用 Stockfish WebAssembly，在瀏覽器 Worker 中執行，避免卡住畫面。
- 每一步至少比較：
  - 實戰著之前的引擎最佳局面；
  - 實戰著之後的局面；
  - 引擎首選著與主要變例（PV）。
- 提供「分析深度／品質」選擇：快速、平衡、深入。深入模式預設用較長的固定思考時間，而非只看淺深度。
- 顯示目前分析到第幾手、可安全取消。
- 初版採單執行緒相容引擎；日後可在 cross-origin isolation 條件滿足時升級多執行緒版。

### 4.3 評估與勝率

- 將引擎評分統一為白方視角的兵值與勝率估計。
- 畫出每個半回合後的白方勝率曲線，可點擊曲線節點跳到對應局面。
- 清楚標示這是「引擎估計的勝率／期望分數」，不是實際對局勝率保證。
- 顯示將殺評估（例如 `#3`）時不得硬轉成一般兵值。

### 4.4 失誤分類與旁白

- 依選手因實戰著損失的評估（centipawn loss）分為：最佳著、好著、可改進、失誤、大失誤。
- 分類門檻為初始可調參數，需在介面或程式中集中定義，不散落在元件內。
- 對每個被選中的回合，以白話呈現：
  - 實戰著造成的局面轉折；
  - 建議著；
  - 為什麼這一步重要（子力、王安全、中心、空間、兵形、威脅、戰術）。
- 第一版的旁白必須誠實區分「引擎可確認的內容」與「規則式策略解釋」。不把沒有語言模型的規則式說明偽裝成深度人類意圖判斷。

### 4.5 互動棋盤與走子清單

- 棋盤可前後一步、點擊走子清單跳轉、播放／暫停回放。
- 高亮實戰著的起訖格，以及引擎建議著。
- 側欄顯示：回合、實戰著、分類、評分、建議著、主要變例、教練旁白。
- 走子清單以顏色／標籤突顯關鍵失誤。

## 5. 非目標（第一版不做）

- Chess.com API、登入、帳號資料同步或自動抓棋譜。
- Lichess／Chess.com 連結解析。
- 在線多人、分享、雲端儲存、帳號系統。
- 即時下棋、對弈模式、開局資料庫。
- 宣稱具備人類教練等級的自然語言判斷。
- iOS／Android／Windows 版與 App Store 發佈。

## 6. 建議的畫面與操作流程

```text
貼上 PGN → 驗證 → 選擇「深入分析」 → 本機 Stockfish 逐手運算
                                              ↓
                                勝率曲線 + 全局摘要
                                              ↓
               點選曲線／走子／棋盤 → 棋盤局面 + 引擎建議 + 教練旁白
```

版面（桌面）：

```text
┌──────────────── 棋局資訊與 PGN 輸入 ────────────────┐
├───────────────┬─────────────────────────────────────┤
│ 評估條  棋盤  │  白方勝率曲線                         │
│   ⬆           ├─────────────────────────────────────┤
│  互動／回放   │  第 18 手：旁白、最佳著、主要變例      │
│               ├─────────────────────────────────────┤
│               │  逐手走子與失誤標籤                   │
└───────────────┴─────────────────────────────────────┘
```

## 7. 分析設計與品質準則

### 評分與失誤

每半回合應以「走子者」的視角比較：

```text
損失 = 該局面最佳著的評估 − 實戰著後的評估
```

黑方時需反轉白方視角，否則會把黑方的好著誤判成失誤。初步門檻：0–15 cp 最佳、16–45 好著、46–100 可改進、101–250 失誤、251+ 大失誤。這些數字是可校準的產品策略，不是棋類真理，集中定義於 `src/review.js` 的 `CLASSIFICATION_THRESHOLDS`。

### 勝率

優先使用 Stockfish 可輸出的 WDL（win/draw/loss）資料推導；若該引擎版本／分析結果沒有 WDL，再以保守的 centipawn sigmoid 作為替代。介面必須說明是「引擎估計」。

### 深入模式

固定深度在不同複雜局面不代表相同思考量。正式深入模式建議採：關鍵點（大幅評估變動或失誤）以較長時間／多 PV 重跑、一般手使用較短分析。這能將有限時間集中在真正需解釋的轉折。

## 9. 待決定事項

- 是否要在分析後將結果保存在瀏覽器本機（IndexedDB），以便日後回看？目前預設不保存。
- 對「深度分析」可接受的大概時長：一局 20 分鐘、1 小時，或更久？這影響每手 time budget。
- 是否要支援設定「我是白方／黑方」，讓摘要只聚焦自己的決策？
- 未來要不要接本機 LLM（例如 Ollama）加強旁白？這仍可完全本機，但會增加模型下載與硬體成本。

## 10. 成功定義

使用者貼入 Chess.com PGN，等候本機分析後，能在互動棋盤上快速回答：

1. 哪一手讓勝率真正翻轉？
2. 當時引擎最想下什麼？
3. 我的實戰著為何有問題，以及局面上犧牲了什麼？
4. 下次遇到相似局面應注意什麼？
